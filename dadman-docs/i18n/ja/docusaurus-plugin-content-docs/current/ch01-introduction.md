## 1.1 DADmanとは?

DADman は、DAD (デジタルオーディオデンマーク) からプロのオーディオハードウェアを設定し、制御するソフトウェアアプリケーションです。 標準的なイーサネットネットワーク上でNTPテクノロジ、およびAvid。 接続されたすべてのユニットの単一制御ポイントです。アナログ入力利得へのアクセスを提供します。 1つの統合インタフェースからの出力レベル、ルーティング、クロック、同期、およびモニタ制御。

DADman は **チャンネルストリップ指向** インターフェイスです。 各接続された各ユニットは、デバイス リストとその入力、出力に表示されます。 ルーティングコントロールは、ミキシングコンソールのチャンネルストリップと同様の概念である垂直チャンネルストリップのセットとして表示されます。 つまり、どのハードウェアユニットを使用しているかに関わらず、DADman インターフェイスは一貫したレイアウトに従います。

### 1.1.1 基本原理: ユニット内でライブ設定

> **注意:** これはDADmanを使う前に理解すべき最も重要な建築コンセプトです。

DADman で構成されるすべての設定 — ルーティング、ゲイン、出力レベル、クロックソース、チャンネルラベル。 他のパラメータはすべて**ハードウェアユニットに保存されます**。DADman ソフトウェアや実行中のコンピュータに保存されません。 DADman はユニットの現在の状態をネットワークから読み込み、それを表示します。 あなたが変更を行うとき、DADmanはそれを格納するユニットにその変更を送信します。

これには実用的な結果があります:

- DADmanが閉じられているか、またはコンピュータがシャットダウンされている場合、ハードウェアユニットは最後に保存された設定で動作し続けます。 オーディオは中断されずに通過します。
- DADman が開かれていて、ユニットがネットワーク上にある場合。 DADman は、たとえそれらの設定が別のコンピュータで最後に設定されたとしても、ユニットの現在の状態をすぐに表示します。
- 工場出荷時のリセットまたはファームウェアの更新後に設定を復元するには、保存された設定ファイルを再読み込みする必要があります。 [第7章7.1 — セッション管理]をご覧ください。

## 1.2 主要な機能

DADman は、互換性のあるハードウェア全体で次の制御機能を提供します。

| 能力                                                 | 説明                                                                                                             |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **アナログ入力制御**                                       | マイク/ラインゲイン、ファントムパワー (+48 V)、パッド、位相反転、チャネルラベル                                                |
| **アナログ出力制御**                                       | 出力レベル、ミュート、チャンネルラベル、出力範囲の選択 (+18/+24 dBu)                                                   |
| **ルーティング行列**                                       | 完全なクロスポイントルーティングマトリクス — サポートされているハードウェア上の最大1500×1,500のクロスポイント。                                                 |
| **時計と同期**                                          | サンプルレートの選択、同期ソースの選択、クロックの調整                                                                                    |
| \*\*モニターコントロール \*\*                                | ソース、出力、折りたたみダウン、遅延、トークバックによるプロファイルの監視                                                                          |
| **マルチユニットコントロール**                                  | 1つのDADmanウィンドウから複数のハードウェアユニットを同時に制御する                                                                          |
| **EuCon統合**                                        | 制御面統合のためのAvid EuControlとの互換性                                                                                   |
| **Pro Tools PRE emulation**                        | MTRXユニットのMIDI制御プリアンプエミュレーション                                                                                   |
| **ルーティングプリセット (Control\|Pack)** | 自動トリガー切り替え\*(v5.8.0以降)\*を備えたユニットあたり最大32個のルーティングプリセット        |
| **マイクゲイングループ**                                     | 複数のマイク入力チャンネルをグループ化して同時利得調整\*(v5.8.1.6以降)\* |
| **設定のバックアップ**                                      | すべてのユニット設定をコンピュータ上のDADman Settings Files (`.dms`)に保存し復元します                                  |
| **単位のクローン**                                        | 同じハードウェアファミリ内の別のユニットにすべての設定をコピーします                                                                             |

## 1.3 ソフトウェアコンポーネントとその関係

DADman は、2 つのコンポーネントのソフトウェアシステムの一部です。 正しいインストールとトラブルシューティングには、2つのコンポーネントの違いを理解することが不可欠です。

### 1.3.1 2つのコンポーネント

| コンポーネント                    | 何をするか                                                                                                                   | 必須項目                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| **DADman**                 | イーサネット経由のハードウェアユニットの設定と制御 — ルーティング、ゲイン、モニタリング、クロック処理                                                                    | サポートされているすべてのハードウェア                  |
| **DAD Thunderbolt 3 ドライバ** | サンダー\|コアインターフェースをDAWで使用するためのコアオーディオ(macOS)またはASIO(Windows)オーディオデバイスとしてコンピュータに表示する | AX64, AXセンター, コア256, Avid MTRXシリーズのみ |

これらの2つのアプリケーションは**独立**です。 彼らは互いに通信しません。 DADman が動作するには Thunderbolt 3 ドライバは必要ありません。 Thunderbolt 3ドライバがオーディオインターフェースをDAWに提示するのに、DADmanは必要ありません。 ただし、Thunderbirdの完全な動作を行うには、_と_の録音を設定するか、オーディオを再生する必要があります。両方をインストールする必要があります。

_[Placeholder: コンピュータとハードウェアユニット間の並列パスとして DADman と TB3 ドライバを示す図 — イーサネット上で通信する DADman TB3ドライバがThunderbolt 3と通信しています_

### 1.3.2 通信パス

A Thunderbird\|コンピュータに接続されたコアユニットは、2つの同時独立した通信パスを使用します:

| パス                | Protocol  | 目的                                               |
| ----------------- | --------- | ------------------------------------------------ |
| **イーサネット**        | TCP/IP    | DADman control — ルーティング、ゲイン、構成                   |
| **Thunderbolt 3** | TB3上のPCIe | オーディオ転送 — コアオーディオまたは ASIO 経由で DAW に表示されるインターフェイス |

イーサネット専用ハードウェア(AX32, DX32R, Pentaシリーズ)はイーサネットパスのみを使用します。 これらのユニットには Thunderbolt 3 ドライバは存在せず、オーディオインターフェースとしてコンピュータに表示されません。 これらのユニットからのオーディオは、MADI、ダンテ、またはAES3上で輸送されます。

## 1.5 ハードウェアファミリーとクローンの互換性

DADman は互換性のあるハードウェアを 3 つの **ファミリー** にまとめます。 ファミリーメンバーシップは、**複製**機能を使用して、どのユニットがお互いに設定を交換できるかを決定します。

クローンを使用すると、1つのユニットからすべての設定を別のユニットにコピーできます。 これは、既知の良好な構成を複数の同一ユニット間で複製したり、設定を置換ユニットに復元したりする場合に便利です。 クローン作成は**同じファミリー**のユニット間のみ許可されています。

| 家族          | メンバー                                                    | メモ                   |
| ----------- | ------------------------------------------------------- | -------------------- |
| **ファミリー 1** | MTRX · AX32 · DX32 · Penta 720 · Penta 721 · Penta 721s | オリジナル世代ルーティングアーキテクチャ |
| **ファミリー 2** | MTRX II · AX64 · AXセンター · Core 256                      | サンダー\|コア生成           |
| **ファミリー 3** | MTRX スタジオ                                               | スタンドアロン版             |

> **注 — 同一でない単位間のクローン作成:** 最高の結果を得るために、ソースとターゲット単位は同一に設定されている必要があります (同じスロット内の同じカード)。 ソースユニットに存在するカードに対して、ターゲットユニット内の同じスロット位置に存在しないカードに対する設定は、ターゲット上で工場出荷時の設定に設定されます。 ターゲットに存在し、ソースに存在しないカードの設定は影響を受けません。
