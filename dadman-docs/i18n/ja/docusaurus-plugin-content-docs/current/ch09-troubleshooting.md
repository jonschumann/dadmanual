## この章の使い方

あなたの問題のカテゴリーに一致するセクションを見つけ、最も密接にあなたが経験しているものを説明する徴候を見つけなさい。 各行は、可能性のある原因と救済策を与えます。 治療法が複数ステップの手順を含む場合、ここで手順を繰り返すのではなく、クロスリファレンスが提供されます。

**Before contacting support**, gather diagnostic information using:  
**DADman menu > About DADman > Copy Information** _(v5.7.2 and later)_  
This copies DADman version, connected device list, OS version, and Thunderbolt driver version to the clipboard. サポートリクエストにこれを含めてください。

## 9.1 ネットワークとデバイス接続

_新しいインストールやネットワークやハードウェアの変更後の一般的なカテゴリです。_

| 症状                                           | 推定可能な原因                                                             | Remedy                                                                                                                                                                                                                                                |
| -------------------------------------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DADman を起動した後にデバイス リストにユニットが表示されません          | ユニットの電源がオンになっていません                                                  | ユニットの電源を入れます。フロントパネルの **準備** LED が緑色であることを確認します                                                                                                                                                                                                       |
|                                              | ユニットが同じイーサネットネットワーク上にありません                                          | ユニットとコンピュータを同じスイッチまたは直接ケーブルで接続します。ケーブルがCat5eまたはCat6であることを確認します。                                                                                                                                                                                       |
|                                              | 異なるサブネット上のユニットとコンピューター                                              | コンピュータ・ネットワーク・インターフェイスをユニットと同じサブネットに設定します (例: `192.168.1.x`)。 フロントパネルの表示でユニットIPを確認                                                                                                                                 |
|                                              | macOS Sequoia (v15): OS レベルの発見問題 | macOS ユーザアカウントからログアウトし、再度ログインします。 Thunderbolt 接続は影響を受けません。 [9.3] と [Ch. を参照のこと。 3, セクション 3.7] |
|                                              | Windows: ファイアウォールがDADman をブロックしています                 | DADman のファイアウォール例外を追加します。 BitDefenderでは、v5.7.2以降に更新                                                                                                                                                                   |
| デバイス リストに単位が表示されますが、切断されています                 | イーサネットケーブルが切断または故障しています                                             | 両端でケーブルをチェック; 破損している場合は交換する                                                                                                                                                                                                                           |
|                                              | ユニットの再起動（例：ファームウェアアップデート後）                                          | 60秒まで待機します。Ready LEDが緑色であることを確認します                                                                                                                                                                                                                    |
|                                              | IPアドレスの重複 — 同じIPを共有する2つのデバイス                                        | すべてのネットワークデバイスで重複するIPを確認し、固有の静的IPを割り当てる                                                                                                                                                                                                               |
| ユニットが接続され、消滅しました                             | ネットワークの中断                                                           | スイッチ、ケーブル、およびポートをチェックします。 DADman は連続的に _(v5.7.0+)_ を再試行します — 接続が復元されると、ユニットは自動的に再表示されます                                                                                                            |
| 一部のユニットのみ表示 (マルチユニットシステム) | サブネットマスクの不一致                                                        | すべてのユニットを確認し、コンピュータが同じサブネットマスクを共有していることを確認します（例：`255.255.255.0`）                                                                                                                                                                                      |
|                                              | IPアドレスを複製                                                           | 一度に1つのユニットを接続して構成し、固有のIPを割り当てます。                                                                                                                                                                                                                      |
| 単位は表示されますが、設定は予期しないものと異なります                  | 起動時に異なる設定で `.dms` ファイルが適用されました                                      | 「起動時に最後のファイルを開く」が有効な場合、DADman は起動時に保存されたファイルをユニットに適用します。 読み込まれたファイルを確認するには、**ファイル > 開く**をチェックしてください。                                                                                                                                                  |

## 9.2 オーディオの問題

| 症状                                                | 推定可能な原因                                                                            | Remedy                                                                                                                                                                     |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| アナログ出力にオーディオがありません                                | 入力が出力にルーティングされていません                                                                | **Con** タブを開きます。入力と必要な出力の間に青色の正方形のクロスポイントが存在することを確認します。                                                                                                                    |
|                                                   | 出力チャンネルミュート                                                                        | **DA** タブをチェックします。**ミュート**が有効でないことを確認します。                                                                                                                                  |
|                                                   | 入力チャンネルミュート                                                                        | **AD** タブをチェックします。**ミュート**が有効でないことを確認します。                                                                                                                                  |
|                                                   | 出力レベルフェーダーの最小値                                                                     | DA出力レベルフェーダーを下流機器の適切な設定に上げる                                                                                                                                                |
|                                                   | サイレントモードの原因となっている時計の不一致                                                            | **Con** タブで: 入力行の黄色の状態インジケーター=同期が失われます。 **Conf** タブに移動し、ソースとサンプルレートを確認します。 [9.5節] を参照。 |

| 既知の信号にもかかわらず信号LEDが点灯しません                          | 入力利得が-42 dBFSしきい値を超えるには低すぎます                                                       | **AD** タブで **MIC ゲイン** を増やします                                                                                                                                              |

| オーディオのクリックまたはポップス                                 | サンプルレートまたは時計の不一致                                                                   | [9.5節 — 時計と同期] をご覧ください。                                                                                |
|                                                   | バッファサイズが小さすぎます(Thunderbolt)                                     | ASIO バッファサイズを大きくします。[9.4節] を参照してください。                                                                  |
| ステレオペアの 1 つのチャンネルのみがオーディオを運びます                    | ステレオリンクが有効になっていません                                                                 | チャンネルペアの **AD** または **DA** タブで Mono/Stereo リンクを有効にする                                                                                                                       |
|                                                   | 接続されているクロスポイントは1つだけです                                                              | **コン** タブで **Shift + クリック** でペアの両方のチャンネルを同時に接続できます                                                                                                                         |

| ADATチャンネル3が88.2または96kHzで動作しません    | v1.0.6.3より前のファームウェアのバグ。            | Thunderbirdをアップデート\|コアファームウェアをv1.0.6.3以降にアップデートする                                                                          |
| 16以上のチャンネルに遅延は適用されません                             | v1.0.6.3より前のファームウェアのバグ。            | Thunderbirdをアップデート\|コアファームウェアをv1.0.6.3以降にアップデートする                                                                          |
| 3G SDIチャネルは起動後に有効になっていません                         | ファミリー1ファームウェアv2.3.6.1 より前のタイミングのバグ | AX32 / DX32R / Penta ファームウェアを v2.3.6.1 以降に更新 _(2022年12月)_                                               |

## 9.7 リセット手順

試行はリストされた順序でリセットされます — 最初に最初に最も柔らかいテスト。

### 9.7.1 設定ファイルの再読み込み

ハードウェアに影響を与えずに保存された設定を復元します:

1. \*\*File > Open…\*\*に移動し、最新の`.dms`ファイルを選択します。
2. DADman ウィンドウですべてのパラメータの更新を確認します。

### 9.7.2 DADman 経由で工場出荷時リセット

> **注意:** ハードウェアユニットに保存されているすべての設定を消去します。 最初に`.dms`ファイルを保存します。

1. デバイスリストでユニットを右クリック(またはmacOSのアクションボタンを使用)します。
2. **ファクトリーリセット**を選択し、プロンプトが表示されたら確認します。
3. After the unit reboots (up to 60 seconds), reload the `.dms` file via **File > Open…**.

### 9.7.3 フロントパネルの IP リセット

ユニットのIPアドレスが不明または誤って設定されていて、DADman経由で接続できない場合:

- **Reconfig** ボタン (ペンまたはポイントされたオブジェクトを備えた背面パネルの小さな穴を介してアクセス) は、電源投入時にユニットを工場出荷時のデフォルトの IP アドレスにリセットします。
- ほとんどのDADハードウェアの工場出荷時のデフォルトIP: `10.0.7.20` — ハードウェアインストールガイドで確認します。
- リセット後、DADman経由で再接続し、デバイスリスト\*\*>ネットワーク設定\*\*経由で再設定します。

### 9.7.4 パワーサイクル

ユニットが応答せず、DADman経由でリセットできない場合:

1. DADman デバイス リストで: ユニット **> 切断** を右クリックします。
2. 主電源スイッチでハードウェアユニットの電源を切ります。
3. 10 秒お待ちください。
4. ユニットに電源を入れます。
5. Ready LEDが緑色になるまで60秒待ってください。
6. デバイス リストに単位が自動的に再表示されます。

### 9.1 DADman ログへのアクセス — macOS

DADman は、macOS Unified Logging システムを介してログエントリを書き込みます。 ログはプレーンテキストファイルとして保存されません。以下の方法で収集してください。

**Console.app (最も簡単な方法):**

1. **Console.app** (Applications > Utilities > Console).
2. 検索フィールドに「DADman」と入力し、Returnを押します。
3. 問題を再現します。 コンソールには DADman ログエントリがリアルタイムで表示されます。
4. 該当するエントリを選択し、右クリックして**コピー**を選択してサポートチケットに貼り付けます。

**ターミナル (タイムレンジ付きログのエクスポート):**

```bash
log show --predicate 'process == "DADman"' --info --last 1h > ~/Desktop/dadman-log.txt
```

必要に応じて `--last 1h` を調整します(例: `--last 30m`, `--last 2h`)。 作成されたファイルはサポートチケットに添付できます。

**クラッシュレポート:**  
DADmanがクラッシュした場合、クラッシュレポートは次のように書き込まれます:

```
~/ライブラリ/ログ/DiagnosticReports/
```

`DADman_<date>_<hostname>.ips` または `DADman_<date>.crash` という名前のファイルを探します。 これらは、**クラッシュレポート**のConsole.appにも表示されます。

**TB3ドライバのログ:**  
Thunderbolt ドライバのログを収集するには:

```bash
log show --predicate 'process == "DADThunderboltDriver" or subsystem CONTANS "ntp"' --info -last 1h > ~/Desktop/tb3-driver-log.txt
```

### 9.9.2 DADman ログへのアクセス — Windows

**Windows Event Viewer:**

1. **Event Viewer** を開く (スタート → 「Event Viewer」を検索)。
2. **Windows ログ > アプリケーション**に移動します。
3. Click **Filter Current Log…** and enter `DADman` in the **Event sources** field.
4. サポートチケットのフィルタされたエントリをコピーまたはエクスポートします。

**アプリケーションデータフォルダ:**  
DADman は設定を保存し、ログファイルを保存します:

```
%AppData%\NTP Technology\DADman\
```

Windows エクスプローラでこのパスを開く (`Win + R` → パスを貼り付け → Enter) し、サポートに連絡するときに見つかった任意の `.log` ファイルを含めます。

> **注意:** 上記のログファイルパスは標準インストールで検証されています。 DADman がデフォルト以外の場所にインストールされている場合、または別のユーザアカウントで実行されている場合、パスは異なる場合があります。 DADサポートは、これらのロケーションに想定されるファイルが含まれていない場合、ガイダンスを提供できます。
