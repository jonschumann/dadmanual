## 8.1 プロファイルの監視 — 設定と管理

### 8.1.1 コンセプト

**モニタープロファイル** (ファイル拡張子` ) mprof`)は、DADman制御ハードウェアユニットの完全なモニタコントローラ構成を定義します。どのソースを監視できるか。 どのスピーカー出力セットが利用可能で、fold-downとup-matchがどのように処理されるか、遅延設定、Talkback ルーティング、および外部メーター出力が利用可能です。

モニタープロファイルは、ユニット設定ファイル (`.dms`) とは完全に分離されます。 異なるプロファイルをロードすることにより、同じ物理的ルーティングと利得構成を複数の異なるモニタリング設定で使用することができ、他のユニット設定を変更することはありません。

> **注意:** モニタープロファイルはハードウェアユニットではなくコンピュータに保存されます。 アプリケーションが起動されるたびに、それらはDADmanにロードされなければなりません(起動時に最後のファイルを開く\*\*がプロファイルで有効になっていない限り)。 DADmanが閉じられているか、コンピュータがシャットダウンされている場合、モニターコントローラはユニットに送信された最後の状態で動作し続けます。 しかし、DADmanがプロファイルをロードして再起動するまで、監視制御は不可能です。

### 8.1.2 モニタープロファイルエディターを開く

モニタープロファイルエディターを開きます。 **Settings > Monitor Profile** (macOS: **⌘<unk> M** / Windows: **Ctrl+Shift+M**)

エディタには5つのタブがあります: **ソース**、**出力**、**Fold Downs**、**Delay**、**MOM**。

### 8.1.3 ソースの設定

ソースとは、オペレータが監視するために選択できるすべての信号パスです。 典型的なソースには、DAWのステレオ出力、ダンテストリーム、ゲストソース、または信頼フィードがあります。

**ソースを追加するには:**

1. **ソース**タブで、右クリックして**新しいソースを追加**を選択します。
2. ソース名をダブルクリックして名前を変更します(例: `Pro Tools`, `Guest`, `Dante Player`)。
3. **Mode**の下で右クリックし、**Set Group Format**を選択します。チャンネル数とフォーマット(Mono、Stereo、5.1、7.1.4など)を選択します。
4. ソース内の各チャンネルに対して、チャンネル割り当てフィールドを右クリックし、ルーティング マトリクスから対応する入力を選択します。 接続されたハードウェアで利用可能なダンテ、MADI、AES3、アナログ入力を使用します。

### 8.1.4 出力セットの設定

**出力セット** はスピーカーの設定として使用される物理的な出力チャンネルのグループを定義します。 複数の出力セットは、異なる物理出力を使用して定義することができます(たとえば、近接フィールドステレオ対)。 周囲)、または異なるトリムレベルを持つ同じ物理出力(例:85 dB SPL vs 75 dB SPL リファレンスレベル)。

**出力セットを追加するには:**

1. **出力**タブで、右クリックして**新しい出力セットを追加**を選択します。
2. 出力セットに名前を付けます(例: `Near Field`, `5.1 Surround`, `85 dB SPL`)。
3. スピーカーの設定に一致する **グループ形式** を割り当てます。
4. 各チャンネルをハードウェア上の物理的なアナログ出力に割り当てます。
5. この出力セットに固定レベルオフセットが必要な場合、**Trim** の値を設定します (複数の参照レベルプリセットに便利です)。

> **注意:** 出力チャンネルがControl\|Packのルーティングプリセットに割り当てられたら、 これらはロックされ、DADman ルーティングマトリクスまたはモニタープロファイルを介して接続できません。 [8.4 — Control\|Pack]をご覧ください。

### 8.1.5 リファレンスレベルと複数の SPL プリセット

リファレンスレベル機能により、誤った調整の危険性がなく、較正済みのSPLにモニタ出力がロックされます。

**リファレンスレベルを設定するには:**

1. テストトーンとキャリブレーションされたSPLメーターを使用して、Monタブのメインレベルフェーダーを所望のモニタリングSPLに設定します。
2. **設定 > モニタープロファイル**で、関連する出力セットを開きます。
3. 出力セットのキャリブレーションされたレベルを**リファレンスレベル**として入力します。
4. セッション中にMonタブで**Ref**を押すと、即座にこのレベルに戻ります。

**同じ物理出力に複数の参照レベルプリセットを作成するには:**

同じ物理出力を指す2つの出力セットを定義しますが、異なるトリム値を指定します。 例:

| 出力セット名          | Outputs | 切り落とし  | キャリブレーションされたSPL |
| --------------- | ------- | ------ | --------------- |
| フィールド 85 dB 付近。 | DA 1–2  | 0 dB   | 85 dB SPL       |
| 近距離フィールド 75 dB  | DA 1–2  | -10 dB | 75 dB SPL       |

両方の出力セットは、format@@0タブで選択可能なスピーカーオプションとして表示されます。 これらのスイッチングにより、物理利得コントロールに触れることなく、即座にSPLレベルを切り替えることができます。

### 8.1.6 折りたたみダウンと一致する

**Fold Downs** タブは、スピーカーフォーマット間で変換する行列を定義します。例えば、7を折りたたむなどです。 互換性チェックのためにステレオにミックスダウンするか、ステレオソースをカスタムスピーカーレイアウトにアップマッチングします。

**標準のfold-down:** DADman には標準のfold-down行列が含まれています(例:5.1からステレオ)。 入力と出力のフォーマットを選択し、DADman は適切なミキシング係数を生成します。

**カスタムマトリクス(up-matchまたはselective routing):** 既存の折りたたみダウンエントリを右クリックし、**Add new matrix**を選択します。 入力と出力形式を同じ値に設定できます — モニターパス内でカスタムルーティングプリセットを効果的に作成します。 この技術により、折り畳み式のアプリケーションが可能になります。

_例 — スピーカーサブセットの選択:_ 7.1.4 → 7.1.4 に「トップスのみ」行列を定義します。 マトリクスエディタでは、4つのオーバーヘッドチャンネル (Lt1, Rt1, Ltm, Rtm) のみを対応する出力にルーティングし、他のすべてのチャンネルは消音します。 メインミックスを変更せずに、format@@0タブでこの「折り畳み」を選択すると、天井スピーカーが効果的にソロになります。

_例 — 低音管理:_ ロー周波数コンテンツを適切なロールオフ係数を持つサブ出力にルーティングするカスタム折りたたみ行列を定義します。 ソースフォーマットに LFE チャンネルが含まれていない場合でも。

### 8.1.7 トークバックの設定

トークバックは、起動時にマイクまたは他のソースをタレントのヘッドフォンフィードにルーティングします。 **設定 > プロファイルの監視 > 出力** でトークバックを構成します。

**Talkback modes** _(v5.7.0 以降):_

| モード          | 行動                                                     | 使用するタイミング:     |
| ------------ | ------------------------------------------------------ | ------------------------------ |
| **切り替え/ラッチ** | 最初のプレスはTalkbackを起動し、2回目のプレスは無効にします。 ラッチ状態を長押しで切り替えます。  | エンジニアがハンズフリートークバックを必要とするスタジオ環境 |
| **RAW**      | Talkback は、ボタンが保持されている間のみアクティブになります。ボタンが放されたときに解放されます。 | 偶発的ラッチが破壊的なブロードキャスト環境          |

> **注意:** RAWモードはMOMハードウェアコントロールとMTRX Studioフロントパネルトークバックボタンに適用されます。 EuConコントロールサーフェスは、この設定に関係なく常にトグル/ラッチモードを使用します。

### 8.1.8 ヘッドフォンフォローコントロール ルーム

デフォルトでは、ヘッドフォンの出力は、コントロールルームスピーカーの選択とは独立した**キュー**ミックスです。 メインのコントロールルームスピーカーで選択されているソースを自動的に追跡するには:

1. **Settings > Monitor Profile > Outputs**では、ヘッドフォン出力の**Monitorモード**を**Master**に設定します。
2. コントロールルームスピーカー出力セットの**モニターモード**を**キュー**に設定します。

**結果:** ヘッドフォン出力はモニターフィード選択に割り当てられます — コントロールルームスピーカーで有効なソースのどれかです。 同じソースがヘッドフォンで再生されます ソースの選択、折りたたみ、およびdim/カットはすべてコントロールルームに従います。

> **注 — 制限:** DADman が動作していない場合、ハードウェアユニットはデフォルトの動作モードに戻ります。 このフォールバックでは、Cue グループのルーティングはハードウェアのデフォルト状態に変換されません。 DADmanがオフラインの場合、ヘッドフォンが制御室に従わないかもしれません。 回避策として、DADman がログイン時に自動的に起動するように設定します。 [セクション8.7 — メニューバーまたはシステムトレイでDADmanを実行する]を参照してください。

## 8.2 マイクゲイングループ \*(v5.8.1 build 6 およびそれ以降) \*

### 8.2.1 コンセプト

[Mic Gain Groups] を使用すると、複数のアナログ入力チャンネルをリンクできるため、1 つのチャンネルでゲインまたはミュートを調整すると、グループ内のすべてのチャンネルが同時に移動します。 チャネル間の相対利得オフセットを維持することです これは、ドラム、オーケストラアンサンブル、合唱団など、マルチマイクのセットアップ用に設計されています。 または位置記録配列。調整によってチャネル間の相対利得関係を維持する必要があります。

MTRX Studio\*\*以外のすべてのハードウェアでは、マイクゲイングループがサポートされています。 ファームウェアのアップデートが必要です(ファミリー1: v2.4.5.1 以降、Thunderbird\|Core: v1.1.1.1 以降)。

**グループ化されたパラメータ:** ゲインとミュートを行います。  
**グループ化されていません:** ファントムパワー (+48 V) とフェーズ反転 (Ø) これらは、チャネルがグループ内にある場合でも個別に制御されます。

### 8.2.2 グループの作成と管理

**グループにチャンネルを追加するには:**

1. **AD** タブで、チャンネルのゲインコントロールを右クリックします(またはチャンネルコンテキストメニューを使用します)。
2. **グループに追加** を選択し、グループ番号を選択します（グループは番号があります。複数の独立したグループを作成できます）。
3. グループに含めるチャンネルごとに繰り返します。

**グループからチャンネルを削除するには:**

ゲインコントロールを右クリックし、**ゲイングループから削除**を選択します。

### 8.2.3 グループの動作

複数のチャンネルがグループを共有している場合:

- グループ化された任意のチャンネルでゲインスライダーを動かすと、**グループ内のすべてのチャンネル**が同じ増分だけ移動します。 チャンネル間の相対オフセットは保持されます。
- グループ化チャンネルをミュートすると、グループ内のすべてのチャンネルがミュートされます。

**個々のチャンネルのオーバーライド — Alt/Option modifier:**

**Alt** (Windows) または **Option** (macOS) を押したまま、チャンネルのゲインやミュートはそのチャンネルのみで行われ、グループをバイパスします。

| アクション                 | Alt/Option             |
| --------------------- | ---------------------- |
| ゲインスライダー上にマウスをドラッグする  | 選択したチャンネルのみを調整します      |
| 半押しキーボード（ゲインスライダーを選択） | 選択したチャンネルのみを調整します      |
| 下のゲイン値フィールドをクリックします。  | 選択したチャンネルのみを調整します      |
| Click Mute            | 選択したチャンネルのみミュート/ミュート解除 |

### 8.2.4 EuConの動作

Avid EuControl サーフェスを介してグループ化されたチャンネルを制御する場合:

- EuConサーフェスでスライダーとノブをゲインすると、グループに影響を与えます(すべてのチャンネルが一緒に動きます)。
- EuConサーフェスからのミュートは、グループ化されたすべてのチャンネルに同時に影響します。

> **注意:** チャンネルごとの設定/オプションのオーバーライドは、DADman のマウス/キーボードでのみ利用できます — EuCon表面からトリガーすることはできません。

## 8.3 単位\*(v5.6.9以降)のクローン設定\*

### 8.3.1 コンセプト

**複製**機能は、同じハードウェアファミリ内のすべての設定を別のハードウェアユニットにコピーします。 既知の良い構成を2番目の同一ユニットに複製する場合に便利です。 設定を復元するか、既存のプロファイルから新しいユニットを初期化します。

クローン作成は同じファミリーグループ内のユニット間のみ許可されます:

| 家族      | メンバー                                                    |
| ------- | ------------------------------------------------------- |
| ファミリー 1 | MTRX · AX32 · DX32 · Penta 720 · Penta 721 · Penta 721s |
| ファミリー 2 | MTRX II · AX64 · AXセンター · Core 256                      |
| ファミリー 3 | MTRX スタジオ                                               |

### 8.3.2 クローン手順

**接続されたユニットから別のユニットにクローンするには:**

1. デバイスリストで**ターゲット**ユニットを右クリックします(設定を受け取るユニット)。
2. \*\*クローンを…\*\*から選択し、リストから元の単位を選択します。
3. クローン操作を確認します。

**保存された設定ファイルから接続されたユニットにクローンするには:**

1. 設定ファイル`.dms`を開くには、 **File > Open…**.
2. デバイス リスト内のターゲット ユニットを右クリックします。
3. **ファイルから複製**を選択し、ロードされた設定ファイル内の関連するソースユニットを選択します。

> **注意:** クローンはターゲットユニットのすべての設定を上書きします。 リカバリが必要な場合は、ターゲットユニットの設定が`.dms`ファイルに保存されていることを確認してください。

### 8.3.3 非同一単位の動作

最良の結果を得るためには、ソースとターゲットの単位を同一に構成する必要があります — 同じスロット位置にインストールされている同じカードタイプです。 設定が異なる場合:

- ソースに存在するカードの設定ですが、ターゲットの **同じスロット位置** にないカードは、ターゲットの工場出荷時の設定に設定されます。
- ターゲットに存在するカードの設定は変更されませんが、ソースに存在しないカードの設定は変更されません。

## 8.4 Control|Pack — ルーティングプリセット \*(v5.8.0 build 8 以降) \*

### 8.4.1 コンセプト

Control\|Pack は、サンダー\|コア製品 (AX64、AX Center、Core 256) 用のルーティングプリセットシステムを提供します。 各ユニットにつき最大32個のルーティングプリセットを定義できます。 最大4つの独立した入力レイヤー(**バケット**)を持つことで、1つのオーディオサンプル内で最大256のソースから256のデスティネーションに同時に切り替わります。

バケット間の切り替えは次のようになります:

- **マニュアル** — 演算子によって制御\|DADman のパックストリップ
- **Automated** — 信号の存在、AE6パイロットトーンインテグリティ、ポートレベルの接続のための入力チャネルを監視する内蔵の信号検出器によって引き起こされます

Control\|PackのプリセットはThunderbird\|Coreハードウェアユニットに保存されます。 複数のDADmanインスタンスから同時に制御することができ、専用のControl\|PackハードウェアパネルからDADman接続なしで制御することができます。

**ファームウェアが必要です:** Thunderbird\|コアファームウェアv1.1.0.3以降。

### 8.4.2 主な仕様

| パラメータ                                   | 値                               |
| --------------------------------------- | ------------------------------- |
| 単位あたりの最大プリセット                           | 32                              |
| プリセットごとの最大バケツ（入力レイヤー）                   | 4                               |
| バケツあたりの最大ソース                            | 256                             |
| プリセットごとの最大出力数                           | 256                             |
| 切り替え時間 (バケット切り替え、自動) | 1 つのオーディオサンプル内で                 |
| 切り替え時間 (手動、直接選択)     | 0個のオーディオサンプル                    |
| 信号検出/トリガ応答時間                            | < 1 ms |
| 信号発生器（内蔵）                               | 正弦波パイロットトーン・AE6デジタルパイロットトーン     |

### 8.4.3 シグナルジェネレーター

各Thunderbird\|コアユニットには、2つの内蔵のシグナルジェネレータが含まれています:

| ジェネレーター             | タイプ                                      | パラメータ                                                                                                  |
| ------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **正弦波パイロットトーン**     | 連続サイン波                                   | レベル: -60 ~ 0 dBFS; 周波数: 20 Hz ~ 20 kHz |
| **AE6デジタルパイロットトーン** | バイナリ繰り返し信号(16進数0xAE6) | 固定パターン                                                                                                 |

信号発生器は、ルーティング マトリックスを介してユニット内の任意の出力にルーティングできます。 AE6信号は整合性チェック用に設計されており、受信側でシグナル・チェーンが未処理で変更されていないことを確認するために検出されます。 AE6信号がサンプリングレートコンバータ、アナログステージ、またはレベルの変化を通過した場合、そのパターンは変化し、認識できません。

### 8.4.4 トリガータイプ

各バケットは最大4つのトリガーソースを割り当てることができます。 3 つのトリガータイプが利用可能です:

| トリガータイプ     | Detects                          | メモ                                                          |
| ----------- | -------------------------------- | ----------------------------------------------------------- |
| **シグナルレベル** | -40 dBFSを超えるオーディオ信号が1ミリ秒以内に存在します | アナログまたはデジタル入力で動作します                                         |
| **AE6**     | AE6デジタルパイロットトーンのデジタル入力           | 正常に検出するには、信号を未処理にする必要があります(SRC、レベル変更なし)。 |
| **ポート**     | 物理ポート接続状態                        | Thunderbolt 3、MADI、DADLink、ADAT、AES3 ポート                    |

### 8.4.5 ルーティングプリセットの設定

**設定 > ルーティングプリセット**からルーティングプリセットエディターを開きます。

設定は4つのステップに従います:

**ステップ 1: ターゲットユニットを選択**

ルーティングプリセットウィンドウの上部にあるドロップダウンメニューから、設定するサンダー\|コアユニットを選択します。 ユニットが接続されていない場合は、**デバイスリストを開く**をクリックして接続してください。

**ステップ 2: ルーティングプリセットを追加**

プリセットリストで右クリックし、**プリセットを追加**を選択します。 プリセットの名前と出力チャンネル数を入力します。 チェックボックスをオンにしてプリセットを有効にします。 プリセットはリスト\*(v5.8.1以降)\*内で並べ替えることができます。

**ステップ 3: バケツとトリガーを設定**

プリセット内のバケットごとに：

1. **ソースセット名** フィールドを右クリックし、バケットの名前を入力します (例: `Pro Tools` 、 `Backup DAW` 、 `Test Generator` )。
2. バケットの **Trigger Priority** を設定します。 検出器が有効な信号を報告するとき、優先度が高いバケットが推奨されます。 すべてのバケットに同じ優先度がある場合、切り替えはマニュアルのみです。
3. 使用可能な入力から最大4つの**トリガーソース**を選択します。 トリガータイプ(シグナルレベル+AE6)を組み合わせて、確実なフェールオーバー検出を実現します。

**自動切り替えロジック:**

- 割り当てられたすべての検出器が OK を出力に送信される、**最も高い優先度** の Bucket です。
- アクティブなBucketの検出器がエラーを報告した場合、システムはすべての検出器で次の最優先バケットに切り替わりますOK。
- 手動オーバーライドは常に利用可能です — バケットボタンをダブルクリックすると、検出器のステータスに関係なく強制的に設定できます。

**ステップ 4: 入力と出力のチャンネルを割り当てる**

「出力チャンネル」列を右クリックして、ユニットで使用可能な出力から出力チャンネルを選択します。 各入力 (バケット) 列を右クリックして、ソースチャンネルを割り当てます。 出力がプリセットに割り当てられたら **ロックされている** — プリセットがアクティブな間は、DADman ルーティングマトリクスやモニタープロファイルを介して接続することはできません。

### 8.4.6 操作

設定が完了すると、Control\|Pack ストリップは、メイン DADman チャンネルストリップの下に表示されます。 各プリセットには、バケットボタン、ソースPPMメーター、出力PPMメーター、トリガーステータスインジケータが表示されます。

**バケツボタンの色の状態:**

| 色     | 意味                                       |
| ----- | ---------------------------------------- |

| **赤** | このバケット上の信号検出エラー — 信号損失またはAE6障害が検出されました   |

**手動モードと自動モードを切り替えます:**

- **緑色のボタンをダブルクリック** → 手動に切り替える (ボタンが青に変わる)
- **青いボタンをダブルクリック** → 再アームの自動化 (ボタンが緑に変わる)

バケットボタンの下にある**状態インジケータ**をトリガーすると、割り当てられた各検出器のリアルタイム合否ステータスが表示されます(バケットあたり0~4のインジケータ)。

## 8.5 EuCon統合

### 8.5.1 EuConを有効にする

DADmanは、EuConプロトコルを介してAvid EuControlと通信し、Avid制御サーフェス(S1、S1)を有効にします。 S6、S6L、MTRX Studioフロントパネル)と、DADmanの監視機能を制御するAvid Controlアプリ。

**EuConを有効にするには:**

1. DADmanで**設定 > EuCon**を有効にします。
2. EuControlが同じコンピュータ上で実行され、コントロールサーフェスまたはアプリに接続されていることを確認してください。

### 8.5.2 DADman モニタリングを EuControl にバインドする

Avid のコントロールサーフェスまたはAvid Controlアプリに表示されるコントロールを監視するには、DADmanはEuControlにバインドされている必要があります。

1. DADman をフォアグラウンドに移動します(アクティブなアプリケーションにするには、DADman ウィンドウをクリックします)。
2. EuControlで**Assign**タブを開きます。
3. DADman のモニタリング割り当てチェックボックスを有効にします(DADman がフォアグラウンドにあるために表示されます)。

> **ヒント:** Avid Control のモニタリングページにマスターフェーダーのみが表示され、その他のコントロールが表示されない場合、バインディングステップは完了していません。 DADman をフォアグラウンドに移動し、Assign タブ手順を繰り返します。

### 8.5.3 DADman へのロック監視

監視はDADmanにバインドされます。 モニタリングセクションをロックできるので、どのアプリケーションが現在フォアグラウンドにあるかに関わらず、DADman コントロールの下に残ります。

1. EuControlの**Assign**タブで、モニタリングセクションがDADmanにバインドされている状態で、**Lock**(またはサーフェスモデルと同等のもの)をクリックします。
2. DAWアプリケーションに切り替えます。 表面のモニタリングセクションは、DADmanを制御し続けています。

これにより、トランスポートおよびチャネルコントロールはDAWに従うことができ、モニタリングセクションはDADmanに恒久的に割り当てられます。これは、ポストプロダクション環境と音楽トラッキング環境のための標準的なワークフローです。

### 8.5.4 EuConとMic Gain Groups

マイクゲイングループが設定されているとき:

- EuConサーフェスのスライダーとゲインノブを使用すると、グループ化されたすべてのチャンネルが一緒に移動します。
- EuConサーフェスからミュートすると、グループ化されたすべてのチャンネルがミュートされます。
- Alt/Optionによるチャンネル毎のオーバーライドは、EuConサーフェスからは利用できません。

### 8.5.5 タッチスクリーンでTalkback ボタンを拡大する

Avid ControlアプリのタッチスクリーンのTalkbackボタンが小さすぎる場合。 **Soft Keys** ページを使用して、Talkback 関数に複数のソフトキーボタンを割り当てます。 複数の隣接するボタンすべてがtalkbackをトリガーし、より効果的なタッチターゲットを与えます。

## 8.6 DADLink _(v5.6.9以降)_

### 8.6.1 コンセプト

DADLinkはDADによって開発された独自のハイチャネルカウント相互接続フォーマットです。 光学SFPモジュールと互換性のあるユニットにミニMADIモジュールスロットを使用して、ユニット間のオーディオを非常に低いレイテンシで転送します。

DADLinkは、複数のDADユニットを直接接続するために設計されています — 例えば、 AXセンターをAX64にリンクして、合計チャネル数を拡大するか、施設内の異なる物理的な場所のユニットを接続します。

**互換性のあるハードウェア:** AX64 · AXセンター·コア256 · DX32R · Penta 720 · Penta 721s _(ファミリーのファームウェアv2.4.1.2から)_

### 8.6.2 チャンネル容量

| サンプルレート                         | DADLink接続ごとのチャンネル |
| ------------------------------- | ----------------- |
| 44.1 / 48 kHz   | 最大 128 チャンネル      |
| 88.2 / 96 kHz   | 最大 64 チャンネル       |
| 176.4 / 192 kHz | 最大 32 チャンネル       |

### 8.6.3 遅延

DADLinkのレイテンシーは約**1マイクロ秒**で、オーディオアライメントの観点からは実質的にゼロです。 DADLink経由で接続されたユニットのすべての入出力は、**Digi遅延**が各ユニットの同じ値に設定されている場合、位相整列です。

### 8.6.4 同期要件

> **注意:** DADLinkに接続されたユニット全体で入力と出力を適切に位相調整するために使用します。 クロックマスターユニットとフォロワーユニットの間の同期ソースとして **DADLink** または **Word Clock** を使用します。 DADLinkネットワーク内のすべてのユニットは共通のクロックソースを共有する必要があります。

### 8.6.5 ハードウェアのインストール

DADLinkは、接続された各ユニットのミニMADIスロットに互換性のある光学SFPトランシーバモジュールを取り付けるために、**miniモジュール**をインストールする必要があります。 SFPトランシーバ間で光ファイバケーブルでユニットを接続します。 特定の SFP モジュールタイプとインストール手順については、DADLink および Mini MADI モジュールインストールガイド ( [digitalaudiosupport.com](https://www.digitalaudiosupport.com) を参照してください。

インストールすると、DADLinkの入出力はMADI、ダンテ、その他のフォーマット入力と並んでDADmanのルーティングマトリックスに表示されます。 フォーマットは、インターフェイスオプションとしてDADLinkが表示されるConfタブに表示されます。

## 8.7 メニューバーまたはシステムトレイでDADmanを実行する\*(v5.7.0以降)\*

### 8.7.1 macOS — メニューバーモード

DADman は、macOS デスクトップ上でのプレゼンスを最小限に抑えるように構成することができ、バックグラウンドで実行すべき恒久的なインストールに適しています。 **DADman > 環境設定**で3つのモードが利用できます。

| モード            | 行動                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------- |
| **ドックのみ**      | DADman は、Dock とタスクバーに表示される通常の macOS アプリケーションとして動作します。 デフォルト。                                                         |
| **メニューバーとドック** | DADman には、macOS システムのメニューバーにアイコンが表示され、すばやくアクセスできます。                                                                  |
| **メニューバーのみ**   | DADman は、メインウィンドウが閉じられるとドックから隠れます。 システムメニューバーアイコンのみが表示されます。 それをクリックすると、DADman メニュー(表示、終了)が表示されます。 |

**メニューバーのみモードからメインウィンドウを表示するには:**

- DADman メニューバーアイコンをクリックして → **表示**
- Finder で `.dms` または `.dmprof` ファイルをダブルクリックします
- **⌘<unk> 1** を押します。
- アプリケーションからDADmanを再度起動する

> **注意:** メニューバーのみモードでは、設定を変更した後もDADman がDockに表示される場合。 Dock アイコンを右クリックして → **Options > Keep in Dock** を無効にします。

> **注意:** メニューバーで DADman を非表示にするモードです。 ユーザーがログアウトした場合やシステムがシャットダウンした場合、環境設定で **常にファイルを保存** が有効になっていない限り、DADman はファイルを保存しません。

### 8.7.2 Windows — システムトレイモード

Windowsでは、**設定 > オプション**でトレイの動作を設定します。

| モード                                    | 行動                                                                     |
| -------------------------------------- | ---------------------------------------------------------------------- |
| **タスクバーのみ (デフォルト)** | DADman は通常の Windows アプリケーションとして動作します。                                  |
| **タスクバーとシステムトレイ**                      | DADman には、クイックアクセス用の tray アイコンも表示されます。                                 |
| **システムトレイのみ**                          | DADman はトレイにのみ起動します。 トレイアイコンを左クリックしてメインウィンドウを表示します。表示/非表示/終了を右クリックします。 |

### 8.7.3 ログイン時に自動起動 (macOS)

DADman をログイン時に自動的に起動させ、設定ファイルを読み込むには:

**Method 1 — macOS ログイン項目:**

1. **システム設定 > 全般 > ログインアイテム**を開きます。
2. **+** をクリックし、アプリケーション フォルダーから **DADman.app** を追加します。
3. 設定で **起動時に最後のファイルを開く** を有効にすると、DADman は正しい `.dms` ファイルを自動的に読み込むことができます。

**Method 2 — AppleScript delay launcher** _(ログインアイテムの非表示が制限されているソノマ以降の場合):_

macOS Sonomaでログイン項目を非表示にする機能が廃止されたため、遅延スクリプトを使用してログイン後にDADmanを起動します:

```applescript
delay 5
tell application "Finder"
  activate
  open application file "DADman.app" of folder "Applications" of startup disk
end tell
delay 8
tell application "System Events"
  set visible of process "DADman" to false
end tell
```

このスクリプトを使用するには:

1. **スクリプトエディタ** (アプリケーション > ユーティリティ > スクリプトエディタ) を開きます。
2. 必要に応じて遅延値を調整するスクリプトを貼り付けます。
3. **アプリケーション** としてエクスポート (**ファイル > エクスポート** → フォーマット: アプリケーション)
4. 結果のアプリケーションを**システム設定 > 全般 > ログインアイテム**に追加します。

スクリプトは5秒遅れてDADmanを起動し、さらに8秒後に隠します。 ハードウェアの起動時間に合わせて遅延を調整します。

## 8.10 モニターソースとしてダンテ仮想サウンドカード

Audinateの\*\*Dante仮想サウンドカード(DVS)\*\*は、MacやPCをネットワーク上でダンテオーディオデバイスとして表示することを可能にします。 コンピュータのシステムオーディオ出力をDanteネットワークにルーティングし、任意のDADman制御ハードウェアユニットにルーティングします。 これは、ダンテをサポートするDAW経由のDAW再生を監視したり、macOS/Windowsシステムオーディオ(YouTube)を使用したりする場合に便利です。 追加のI/Oなしでメインモニターシステムを介してSpotify、リファレンストラック)。

### 8.10.1 前提条件

- ダンテ仮想サウンドカードがインストールされ、ホストコンピュータにライセンスされています
- ダンテコントローラがインストールされました（Audinateから無料）
- ダンテ入力(AXセンター、コア256、AX64、AX32、ダンテ拡張カードなど)を備えたDADman制御ユニット。

### 8.10.2 構成手順

**ステップ 1 — DVSを起動して設定**

1. Dante仮想サウンドカードアプリケーションを開きます。
2. チャンネル数を必須に設定します(例: 7.1 または 7.1.2 ソースの場合は **8×8** )。
3. **Start** を押してDVSサービスを有効にします。 コンピュータがネットワーク上にダンテデバイスとして表示されます。

**ステップ2 — ダンテコントローラのハードウェアユニットにDVSをパッチします**

1. **ダンテコントローラ**を開きます。
2. **Routing** 行列で、DVS 送信機を見つけます(コンピュータのホスト名の下に表示されます)。
3. DVS出力をDADmanハードウェアユニット上の所望のDante入力チャンネルにルーティングします(e. 。、DVS は、1–8 → MTRX ダンテ入力 1–8 または AX センター ダンテ入力 1–8) を出力します。

**ステップ 3 — システムオーディオ出力を DVS (macOS)に設定**

**Option**を押したままメニューバーのmacOSボリュームアイコンをクリックし、システム出力デバイスとしてDante仮想サウンドカードを選択します。 あるいは、**システム設定 > サウンド > 出力**で設定してください。

**ステップ 4 — DVDman Monitor ProfileにDVSソースを追加**

1. DADmanでは、**設定 > モニタープロファイル**に移動します。
2. **ソース**タブで、右クリックして**新しいソースを追加**を選択します。
3. ソースに名前を付けます(例: `DVS`, `System Audio`, `Mac Output`)。
4. **モード**列を右クリックし、**グループフォーマットを設定**を選択します。— DVS構成(Stereo、5.1、7.1など)に一致するチャンネル数を選択します。
5. チャンネルごとに、チャンネル割り当てを右クリックし、DVS信号を受信する対応するダンテ入力チャンネルを選択します (ダンテコントローラにパッチを当てます)。

**ステップ5 — 確認**

DADman **Mon** タブに戻ります。 DVSソースは選択可能なモニターソースとして表示されるはずです。 コンピュータでオーディオを再生します。DVSソースの行にメーターが表示されます。

> **注意:** DADman が設定された DVS ソースと共にアクティブなモニター・プロファイルをロードしている間のみ、DVS ソースがモニター・ソース・リストに表示されます。 別のプロファイルがロードされている場合、正しいプロファイルが再ロードされるまでDVSソースにアクセスできません。

## 8.11 アナログ出力レベルの設定

**DA**タブのアナログ出力レベルコントロールでは、ハードウェアユニットのデジタルドメイン(dBFS)とアナログ出力レベル(dBu)の信号アライメントを設定します。 これはキャリブレーション設定です。これは動作レベル制御ではありません。

### 8.11.1 コンセプト

DA出力レベルスライダーは、0dBFSに対応するアナログレベルを指定します。 モニタリングレベルは制御されません。モニタリングボリュームは**モン**タブのフェーダーによって制御されます。 DA出力レベル設定は、ハードウェアのアナログ出力を下流機器のヘッドルーム要件に合わせるためにのみ存在します。

**例:** DA出力レベルが+18 dBuに設定されている場合、0dBFSデジタル信号はアナログ出力で+18 dBuを生成します。 下流機器(パワーアンプまたはアクティブモニタ)クリップ+18 dBuの場合 0dBFSの信号はアンプをクリップします。そのため、DAレベルは下流機器の最大入力仕様に合わせて設定する必要があります。

> **注意:** DAの出力レベルを高く設定することは必ずしも有利ではありません。 下流機器クリップが +18 dBu のときに +24 dBu を設定すると、入力がデジタルフルスケールの前に 6 dB のクリップになります。 DA出力レベルは、接続されたアンプまたはモニタの最大入力仕様に常に一致します。

### 8.11.2 出力レベル範囲

DAライン出力(DB25コネクタ)は、2つの選択可能な最大出力レベル範囲を提供します。

| Range                  | Slider span              |
| ---------------------- | ------------------------ |
| -66 dBu から **+18 dBu** | デフォルト                    |
| -60 dBu から **+24 dBu** | **6 dB ゲイン** ボタンで有効になります |

チャンネルの **6 dB ゲイン** ボタンを有効にすると、出力範囲が +24 dBuまで拡張されます。 これは、最大入力+24dBuのプロ仕様機器に接続する場合に適しています。

### 8.11.3 チャンネル毎の設定

異なる出力チャネルを異なるアナログレベルに設定することができ、単一のユニットからの混合機器接続を可能にします。 たとえば、+18 dBuでステレオパワーアンプのクリッピングから供給された近フィールドモニタを+18 dBuに設定できます。 一方、+24dBuヘッドルームを備えたアンプから供給されたサラウンドスピーカーは、同じユニットで+24dBuに設定できます。

## 8.12 SPQスピーカー処理カード

**SPQ(Speaker Processing)カード**は、互換性のあるDADハードウェアユニット(AX32およびMTRX)用のオプションのDSP拡張カードです。 アナログモニタ出力にチャネルごとのパラメトリックEQ を提供し、信号経路内の外部プロセッサなしでハードウェア内スピーカとルーム内の補正が可能です。

> **注意:** SPQカードはハードウェアオプションです。 それは物理的にユニットにインストールする必要があります。 SPQカードが存在しない場合、format@@0タブはDADmanには表示されません。

### 8.12.1 SPQ ワークフローの概要

一般的なSPQワークフローは次のとおりです。

1. **音響測定ソフトウェアを使用してルーム**を測定します。（例：無料の**Room EQ Wizard**、roomeqwizard.comで利用可能） リスニング位置に校正された測定マイクを使用します。
2. 測定ソフトウェア内の測定結果から**EQ 補正フィルター**を生成します。
3. **フィルター** を SPQ タブから DADman にインポートします。 DADman は、Room EQ Wizardから互換性のあるエクスポート形式でEQ データを受け付けます。
4. **修正を適用** — SPQカードはインポートされたフィルタ係数を使用してアナログ出力をリアルタイムで処理します。

### 8.12.2 DADman の SPQ タブ

接続されたユニットで互換性のあるSPQカードが検出されると、format@@0タブがDADmanに表示されます。 format@@0タブから次のことができます:

- 出力ごとのEQ 曲線を表示および編集します
- Room EQ ウィザードから測定データをインポート
- 出力チャンネルごとのSPQ処理を有効またはバイパスする
- ユニット設定ファイル (`.dms`) の一部としてSPQ設定を保存します

> **注意:** SPQの設定は、モニタープロファイルではなくハードウェアユニットに保存されます。 DADmanセッションでは、プロファイルをロードする必要はありません。

## 8.13 Dolby Atmos 監視ワークフロー

DADmanのモニタプロファイルシステムは、シングルユニット構成から64チャンネル構成までのドルビーアトモス監視をサポートしています。 以下は、DADman制御ユニットを使用した典型的なドルビーアトモス監視信号経路の概念です。

### 8.13.1 シグナルフロー 概要

ドルビーアトモスの典型的な監視チェーン:

```
Pro Tools (Atmos session)
      ↓ (DADLink / MADI / Dante)
Dolby Renderer (e.g., Dolby Atmos Mastering Suite / Renderer)
      ↓ (speaker feeds — up to 9.1.6 or beyond)
DADman hardware unit (DA outputs)
      ↓ (analogue)
Speaker amplifiers and speakers
```

DADman は、レンダラーのスピーカー出力フィード上で、最終的なモニター制御レイヤー(ソース選択、レベル、折り畳みダウン、およびdim/カット)を処理します。

### 8.13.2 カスタムグループ形式の作成

標準の DADman グループ形式は最大 7.1.4 をカバーします。 もっと大きなアトモスの設定 (9.1.6, 7.1.6など) では、**カスタムグループ形式** を定義する必要があります。

1. **Settings > Monitor Profile**で**Outputs**タブを開きます。
2. 右クリックして**カスタムグループ形式を追加**を選択します。
3. チャンネル数とスピーカーレイアウトラベルを定義します（例：L、C、R、Ls、Lss、Lts、Lts、Rts…）
4. 書式を保存し、関連する出力セットに割り当てます。

### 8.13.3 Dolby Renderer からのソースと戻り値

モニタープロファイルに、レンダラー出力のセットを個別のソースとして追加します。

| ソース                         | チャンネル                                                                | 目的                              |
| --------------------------- | -------------------------------------------------------------------- | ------------------------------- |
| アトモスがいっぱいです                 | 9.1.6 (またはベッドを設定) | レンダラーからのアトモススピーカーフィード           |
| Stereo Downmix              | 2.0                                                  | レンダラーのITUステレオダウンミックスを返します       |
| バイノーラル                      | 2.0                                                  | レンダラーのヘッドフォンバイノーラルの戻り値          |
| 5.1 Downmix | 5.1                                                  | レンダラーの5.1 互換性折り |

### 8.13.4 アトモスの折りたたみダウン

**Fold Downs** タブを使用して、レンダラー上のソースの切り替えを必要としない互換性監視オプションを追加します — 例えば、 Atmosスピーカーチャンネルのステレオ和をDADmanに直接適用して、素早いモノラルチェックや狭いステレオチェックを行うfold-down。 これらのサプリメントは、置き換えるのではなく、レンダラー自身のダウンミックス出力です。

> **注意:** Dolby仕様のダウンミックスでは、必ずDADman fold-downではなく、Dolby Rendererのダウンミックス出力を使用してください。 DADman fold-downはドル認証プロセスではありません。

## 8.14 ダンテ上の LTC

Danteインタフェースを備えたDADman-controlのユニットは、\*\*LTC(Linear Timecode)\*\*をDanteオーディオチャンネル内に搭載できます。 これにより、専用のタイムコード配線を行うことなく、同じネットワーク上の任意のユニットにタイムコードソースをダンテネットワークに分散することができます。

### 8.14.1 コンセプト

LTCは、オーディオ波形内のSMPTEタイムコードをエンコードするオーディオ周波数信号です。 それはオーディオと同じ周波数範囲を占めるためです モノラルオーディオ信号のように、Danteチャンネルを経由してルーティングすることができます。特別なDante設定は必要ありません。

### 8.14.2 設定

**ダンテ越しにLTCを送るには:**

1. LTC ソース(ハードウェアタイムコードジェネレータ、DAW出力など)を接続します。 DADmanハードウェアユニットで利用可能なアナログ入力またはデジタル入力に変換します。
2. DADman の **Con** タブで、LTC 入力を Dante 出力チャンネルにルーティングします。
3. **ダンテコントローラ**では、ダンテチャネルをネットワーク上の任意の受信ユニットにルーティングします。

**接続されたユニットでLTCを受け取るには:**

1. ダンテコントローラでは、LTC Danteチャネルを受信ユニットの適切な入力にルーティングします。
2. LTCを受け入れるダウンストリームデバイスのタイムコード入力にその入力を接続します。

> **注意:** LTCはアナログ波形です。 サンプルレートコンバータを通過すると、タイムコード信号が破損する可能性があります。 ダンテネットワーク内のすべてのユニットが、タイムコードチャンネルにSRCが挿入されないように、同じクロックソース(Word クロック、PTP/IEEE 1588など)を共有していることを確認します。 [8.6.4 — DADLink同期要件]を参照してください。

## 8.15 MIDIコントロールとプロツールPREエミュレーション

DADmanはMIDIを介してPro Toolsに接続することができます。 Pro ToolsがDADマン接続ユニットのプリアンプ利得コントロールを**Avid PRE**ハードウェアのプリアンプコントロールと同じように扱うことができます。 これにより、Pro Toolsのリモートプリアンプ制御機能により、DADmanにフォーカスを切り替えることなく、Pro ToolsのI/Oセットアップまたは互換性のあるコントロールサーフェスから直接DADmanハードウェアの入力ゲインを調整することができます。

### 8.15.1 概要

Pro Tools PRE エミュレーションがアクティブな場合:

- Pro ToolsはMIDIゲインチェンジメッセージをDADmanに送信
- DADmanはこれらを接続されたハードウェアユニットのアナログ入力のゲイン調整に変換します
- DADman ADタブには現在のゲイン値が表示され、Pro Toolsからの変更はリアルタイムで反映されます。

### 8.15.2 設定

**Pro Tools PREエミュレーションのMIDIコントロールを有効にするには:**

1. DADmanコンピュータとPro Toolsシステム(macOS上のネットワークMIDI、USB MIDI、またはIACドライバ)の間にMIDI接続が存在することを確認します。
2. DADmanでは、**Settings > MIDI**に移動し、MIDI入力と出力ポートを接続に合わせて設定します。
3. Pro Toolsの**I/O セットアップ**では、DADmanに対応するMIDI接続を使用するようにプリアンプページを設定します。

> **注意:** MIDIチャンネルの割り当てとコントローラーのマッピングは、ProツールのバージョンとMTRX/DADユニットの設定によって異なります。 ハードウェアモデルの正しいMIDIパラメータテーブルについては、関連するAvid MTRXのドキュメントまたはDADのサポートを参照してください。
